# Database Schema Fix - Migration 20260202

## Summary

This migration fixes missing tables and columns identified during a comprehensive database schema audit.

## Issues Fixed

### 1. Missing `cognitive_memory` Table/View
- **Problem**: `packages/api/src/routes/assistant.ts` references `cognitive_memory` table that doesn't exist
- **Solution**: Created a view `cognitive_memory` that aliases the `memories` table
- **Impact**: Assistant API can now load user memories without errors

### 2. Missing `summary` Column in `brief_history`
- **Problem**: `rpc_get_unified_alerts()` function references `brief_history.summary` column that doesn't exist
- **Solution**: Added `summary TEXT` column to `brief_history` table
- **Impact**: Unified alerts system can now display insight summaries correctly

### 3. Missing Core Tables
- **Problem**: Core tables may be missing in some database instances
- **Solution**: Created tables with `IF NOT EXISTS`:
  - `conversations` - User conversation metadata
  - `messages` - Conversation messages with multimodal support
  - `memories` - Long-term memory storage
  - `agendamentos` - User appointments and schedules

## Database Schema Changes

### Tables Created/Updated

#### 1. `conversations`
```sql
CREATE TABLE public.conversations (
    id UUID PRIMARY KEY,
    user_id UUID NOT NULL,
    title TEXT,
    mode TEXT,
    created_at TIMESTAMPTZ,
    updated_at TIMESTAMPTZ
);
```

#### 2. `messages`
```sql
CREATE TABLE public.messages (
    id UUID PRIMARY KEY,
    conversation_id UUID NOT NULL,
    role TEXT CHECK (role IN ('user', 'assistant', 'system', 'system_summary')),
    content TEXT NOT NULL,
    origin TEXT DEFAULT 'text',
    attachments JSONB DEFAULT '[]',
    created_at TIMESTAMPTZ
);
```

#### 3. `memories`
```sql
CREATE TABLE public.memories (
    id UUID PRIMARY KEY,
    user_id UUID NOT NULL,
    key TEXT NOT NULL,
    content TEXT NOT NULL,
    type TEXT DEFAULT 'misc',
    importance INTEGER DEFAULT 1,
    status TEXT DEFAULT 'active',
    source TEXT DEFAULT 'inferred',
    tenant_id UUID,
    created_at TIMESTAMPTZ,
    updated_at TIMESTAMPTZ,
    UNIQUE (user_id, key)
);
```

#### 4. `cognitive_memory` (VIEW)
```sql
CREATE VIEW public.cognitive_memory AS
SELECT * FROM public.memories WHERE status = 'active';
```

#### 5. `agendamentos`
```sql
CREATE TABLE public.agendamentos (
    id UUID PRIMARY KEY,
    user_id UUID NOT NULL,
    titulo TEXT NOT NULL,
    data DATE NOT NULL,
    hora TIME,
    descricao TEXT,
    status TEXT CHECK (status IN ('pendente', 'confirmado', 'cancelado', 'concluido')),
    criado_em TIMESTAMPTZ,
    updated_at TIMESTAMPTZ
);
```

#### 6. `brief_history` (UPDATED)
```sql
ALTER TABLE public.brief_history 
ADD COLUMN summary TEXT;
```

## Security Features

### Row Level Security (RLS)
All tables have RLS enabled with policies:
- Users can only view/insert/update/delete their own data
- Service role has full access for background operations

### Indexes
Performance indexes added on:
- `conversations(user_id, updated_at DESC)`
- `messages(conversation_id, created_at DESC)`
- `memories(user_id, status, updated_at DESC)`
- `memories(importance DESC, updated_at DESC)`
- `agendamentos(user_id, data)`

### Triggers
Auto-update `updated_at` timestamp on:
- `conversations`
- `memories`
- `agendamentos`
